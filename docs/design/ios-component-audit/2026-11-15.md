## 明确问题

### F1 · P1：异步任务开始后立即关闭弹窗

- 位置：`HomeView.swift:150,171,199,725`；`TrashView.swift:57,77,94`；`SettingsView.swift:932,943`；`NoteEditorView.swift:314,427`。
- 事实：`AUIDialogAction(closes: true)` 的同步 handler 仅创建 `Task`，随后 AaronUI `Overlay.swift:393` 立即关闭。重命名还在 `HomeView.swift:729` 提前清空 `noteToRename`。失败后用户离开原任务，没有保留可直接重试的弹窗上下文。
- 规范：[Dialog Basic · Best Practices](http://localhost:5680/components/dialog-basic#best-practices)，要求实际成功后关闭，失败保留草稿，不在 pending 时关闭。来源 `ui://component/dialog-basic#best-practices`，读取 2026-11-15。
- 结论：**违例，静态确定**。包括删除、恢复、清空、清理、重命名和合并任务；批量删除同类代码当前入口关闭。
- 最小建议：调用方维护 pending / error，任务完成后再关闭；配置 `loading` / `disabled`，失败保留对象与草稿。重命名错误应回到原输入任务，而非丢失目标后打开另一条错误通知。

### F2 · P2：纯通知被包装成主操作

- 位置：`HomeView.swift:206,217,222`，`TrashView.swift:107`，`NoteEditorView.swift:308`，`SettingsView.swift:312,926`。
- 事实：“操作结果”“错误”“保存失败”“加密笔记”等纯提示都传 `primary: AUIDialogAction("确定" / "知道了")`；`IOSAaronUI.swift:36` 甚至把 primary 设为必填，无法表达只有次操作的通知。
- 规范：[Dialog Basic · Composition](http://localhost:5680/components/dialog-basic#composition)、[Dialog Label](http://localhost:5680/docs/dialog-label)，通知只保留次级 outlined acknowledgement，不设置主 CTA；操作按钮要说明实际结果，不能用泛化的 OK / Submit。
- 结论：**违例，静态确定**。不是要求把所有信息 Dialog 都改成 Toast；需按通知、需回应的故障、只读查看分别配置。
- 最小建议：允许 `primary=nil`，纯通知使用次操作“知道了”；存在恢复操作时把具体恢复动作作为 primary，避免一概使用“确定”。

### F3 · P2：失败区域借用 Empty State，重试会移除错误上下文

- 位置：`HomeView.swift:289,833`；`IPadNoteWindow.swift:121–125`。
- 事实：初始化失败和独立窗口加载失败均使用 `AUIEmptyState`；重试分别重新初始化、设置 `.loading`，把错误标题、原因与恢复按钮整块换掉。
- 规范：[Error State · Usage](http://localhost:5680/components/error-state#usage)、[Empty State · Usage](http://localhost:5680/components/empty-state#usage)：失败与确认无内容分开；重试期间保留错误标题和说明，只让动作进入 loading。
- 结论：**违例，静态确定**。当前 SwiftUI 包检索不到 `AUIErrorState`，属于组件能力缺口加调用方状态问题，不能直接建议调用不存在的 API。
- 最小建议：增加保持错误信息的应用侧恢复状态；后续在组件库获得授权时补齐 Error State，再统一接入。不要把真实无结果状态改成错误。

### F4 · P2：清空回收站图标按钮缺少明确的可访问动作名

- 位置：`TrashView.swift:45–49`。
- 事实：只有 `Image(systemName: "trash")`，点击实际打开“清空回收站”，没有 `.accessibilityLabel`；系统符号名称不能准确说明作用范围和后果。当前其他关闭、新建、复制按钮已有显式标签。
- 规范：[Button · Best Practices](http://localhost:5680/components/button#best-practices)：icon-only button 需有可访问的动作名。
- 结论：**违例，静态确定**；未声称已完成 VoiceOver 真机读出验证。
- 最小建议：明确命名“清空回收站”。功能关闭的批量完成按钮和加密切换图标也应在重新启用前补齐标签。

### F5 · P2：重复的卡片操作缺少目标区分

- 位置：`NoteCardView.swift:39–50`；`TrashView.swift:214–234`。
- 事实：每张卡片使用同一个“笔记操作”名称；当前构建的语义快照中三个菜单按钮均为这个名称。卡片上下文没有进入按钮名称，单独按动作浏览时不能区分目标。
- 规范：[Utility Button · Best Practices](http://localhost:5680/components/utility-button#best-practices)：相邻的重复局部操作应在可访问名称中包含目标对象。该规则针对局部操作职责，适用于当前 Button / Menu 等价实现。
- 结论：**违例，静态与当前构建语义快照支持**。未验证屏幕阅读器完整导航顺序。
- 最小建议：例如“欢迎使用 Seal Note，笔记操作”，保持菜单和卡片主打开动作独立。

### F6 · P3：时间文本未遵循关联 Doc 的绝对时间格式

- 位置：`NoteCardView.swift:148`，`EncryptedCardView.swift:190`，`TrashView.swift:238`，`DateFormatters.swift:16`。
- 事实：所有日期固定输出 `yyyy-MM-dd HH:mm`，即便当天或同年也带年份，并使用连字符。
- 规范：[Time Display · Absolute Time](http://localhost:5680/docs/time-display#absolute-time)，精确时间模式下当天为 `HH:mm`，同年其他天为 `MM/DD HH:mm`，跨年为 `YYYY/MM/DD HH:mm`。
- 结论：**与当前 Doc 不一致，静态确定**；不应借此修改共享日期工具并连带改变 macOS。项目当前成文设计未给出这些时间格式的明确例外。
- 最小建议：iOS 显示层采用对应格式，或确认并记录产品需要始终显示完整绝对日期的例外；不强制切换相对时间。
