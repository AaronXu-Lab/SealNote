## 修改与验证

| 问题 | 修复 | 验证证据 |
| --- | --- | --- |
| F1：异步提交提前关闭 | iOS 专用 `snAsyncDialog` 等待 async throws 操作完成；进行中显示 loading、禁用输入和取消、阻止 Escape 关闭；错误留在原弹窗，目标与草稿保留；成功关闭后再执行后续呈现 | 防重复提交、失败后重试测试通过；iPhone 上实际重命名、列表删除、回收站恢复、编辑器删除及清理结果提示均通过 |
| F2：通知错误占据主操作 | `snDialog` 的 primary 改为可选；纯结果、错误和说明使用 secondary “知道了”；实际提交保留原主操作 | 清理空白笔记结果实际呈现只有 outlined “知道了”，点击后返回原设置页；[截图](2026-11-15-fixed-notice.jpg) |
| F3：错误用 Empty State、重试移除说明 | 新增 iOS 应用侧 `SNErrorState`，保留失败标题与原因，只让恢复动作进入 loading；独立窗口重试不再切回整页 Loading；首页保留错误分支至请求结束 | 初始化首次存储失败、恢复后重试进入 ready 的回归测试通过；错误页结构与状态路径静态核对；未在实际运行 App 中注入存储故障 |
| F4：清空图标未命名 | 回收站 toolbar 按钮显式命名“清空回收站” | 当前 iPhone 语义快照包含 `button|清空回收站` |
| F5：重复局部动作无目标区分 | 普通笔记与回收站菜单名称包含该笔记标题 | iPhone / iPad 语义快照区分不同标题；重命名后名称立即更新为 `UI audit renamed，笔记操作` |
| F6：绝对时间格式不一致 | 新增仅 iOS 可见的格式化入口：当天 `HH:mm`，同年其他日 `MM/dd HH:mm`，跨年 `yyyy/MM/dd HH:mm`，非法日期 `—`；普通卡片、加密卡片、回收站接入 | 24 小时制、非法值及纽约时区本地日界 / 年界测试通过；两台模拟器当天卡片显示时分 |

异步删除仍先通过 EditorSession 刷新，不新增正文保存任务。刷新失败时保留编辑器与删除任务；真正完成删除后，等待确认弹窗关闭再关闭编辑器。合并提示使用独立的呈现状态，避免存储层在合并尚未完全结束时修改检测标记而提前卸载弹窗。

共享 `VaultStore.initialize()` 的错误重置仅放在 `#if os(iOS)` 内，解决成功重试仍被旧 `.error` 拦住的问题。日期、卡片标签及新增测试也受 iOS 编译条件保护；Home / Settings / NoteEditor / Trash 原本已从 macOS Target 排除。对全部 7 个修改过的共享 / 测试文件比对 macOS 条件编译投影，内容一致。没有运行或修改 macOS 应用。

## 实际交互范围与限制

iPhone 使用本次创建的临时笔记验证：创建并保存 → 重命名 → 删除到回收站 → 恢复 → 编辑器内删除。最后临时笔记 `UI audit renamed` 留在模拟器回收站，没有清空或永久删除任何既有记录。原有三篇笔记没有修改。

iPhone 和 iPad 均验证空标题禁用保存；iPad 输入临时草稿后取消，原标题保持不变。工具输入前需先 focus 字段；早先未 focus 的输入尝试没有改变字段，后续已用实际字段值确认输入与清空结果。

失败保留 / 重复提交通过受控异步测试验证；没有对实际保险库制造磁盘失败，没有执行真实 iCloud 合并。长时间加载与系统级 VoiceOver、减少动态效果、动画完成 / 卸载事件仍未进行全覆盖。原 MCP Example 读取失败的限制仍沿用，不能据两张截图认定已完成所有 Example / 状态对齐。
